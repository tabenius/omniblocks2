This structured brief is designed for Claude Code (or any high-end LLM engineer). It provides the architectural context, the tech stack, and a step-by-step implementation plan to build a dual-purpose Block Editor.Project Brief: Headless Block Editor (Web + Email)1. The Core MissionBuild a drag-and-drop block editor that stores content in a neutral JSON schema. This single source of truth must render to two distinct targets:Web: High-performance, SEO-friendly React/Next.js components (using Tailwind).Email: Table-based, Outlook-safe HTML (using react-email).2. The Tech StackFramework: Next.js 15+ (App Router).Editor Engine: Craft.js (Headless Drag-and-Drop).Styling: Tailwind CSS (Editor/Web) + Inline Styles (Email).Email Engine: @react-email/components & @react-email/render.Data Format: Serialized Craft.js JSON Node Map.3. Block Library Requirements (The DSL)The system must support the following blocks via a unified schema:Hero: USP Headline, subtext, CTA button, Image.LayoutBlock: A dynamic $N$-column grid ($N=1$ to $4$) using LinkedNodes.FeaturesGrid: 3-column icon/heading/text blocks.PricingTable: 3-column plans (Web) $\rightarrow$ Stacked plans (Email).Accordion: Interactive FAQ (Web) $\rightarrow$ Static list (Email).Implementation Plan for Claude CodePhase 1: Foundation & Primitives[ ] Initialize Next.js project with Tailwind and @craftjs/core.[ ] Create a lib/resolver.ts to map component names to React components.[ ] Implement Container and Column primitives with connect and drag refs.[ ] Set up the Editor provider in a Client Component (components/editor/EditorShell.tsx).Phase 2: The Multi-Column Layout Block[ ] Build LayoutBlock using LinkedNodes for columns (column-0, column-1, etc.).[ ] Map props.columns to a CSS Grid template for the editor view.[ ] Create LayoutSettings.tsx to allow users to toggle column counts and adjust gap and padding props.Phase 3: The Web Renderer (SEO Optimized)[ ] Create a recursive renderNode function that traverses the Craft.js JSON map.[ ] Ensure this function runs in Server Components to allow for Static Site Generation (SSG).[ ] Map JSON props to Tailwind classes (e.g., props.padding $\rightarrow$ style={{ padding: props.padding }}).Phase 4: The Email Renderer (React Email)[ ] Create a mirror directory components/renderers/email/.[ ] Implement an EmailLayout component that converts LayoutBlock props into <table>/<tr>/<td> structures.[ ] Build the "Email Walker": A specialized version of the recursive renderer that returns @react-email components.[ ] Integrate he or html-entities for safe text encoding.Phase 5: Persistence & Actions[ ] Create a Server Action to save the serialized JSON string to the database.[ ] Implement a "Preview Email" toggle that renders the current state using the Email Renderer.[ ] Add a Telegram export utility that strips unsupported tags and converts text to Telegram-safe HTML entities.Critical Instructions for Claude:Headless Priority: Never store raw HTML. Always treat the Craft.js JSON as the only source of truth.Prop-Driven Styling: Styles like colors, padding, and alignment must be stored as props in the JSON, not hardcoded Tailwind classes, so the Email Renderer can read them.No Scraping: Do not attempt to "scrape" the editor's DOM. Always use the "State Traversal" method to generate the Email/Static outputs.Next Step for Claude: Start by generating the LayoutBlock and the EditorShell to establish the drag-and-drop environment.
